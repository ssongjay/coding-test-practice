## 짧은 문제 요약

## 최초 풀이의 판단과 복잡도

- 첫 원소를 먼저 추가하고 tmp에 저장해 다음 원소와 비교할 기준을 만들었다.
- 같은 값에서 continue하면 tmp 갱신을 건너뛰지만 현재 값이 tmp와 같으므로 비교 기준은 달라지지 않는다.
- tmp는 첫 반복에서 할당된 뒤 두 번째 반복부터 읽힌다. 첫 원소 분기와 할당 위치를 함께 봐야 한다.
- 반복마다 상수 시간의 비교·인덱스 접근·분할 상환 O(1)의 append만 수행하므로 전체 시간 O(n)이다.
- 결과 리스트는 최악 O(n) 공간이고, 결과를 제외한 추가 상태는 O(1)이다.
- 같은 값이 떨어져 다시 나오면 남겨야 한다. 전체 중복을 없애는 set과 요구사항이 다르다.

## 복습할 다른 표현

아래는 풀이 후 살펴볼 추천 코드다. 최초 답안은 solution.py에 그대로 둔다.

```python
def solution(arr):
    answer = []
    for value in arr:
        if not answer or answer[-1] != value:
            answer.append(value)
    return answer
```

별도 tmp 대신 결과에 마지막으로 남긴 값과 비교한다. 결과가 비어 있을 때 not answer가 참이므로 첫 원소를 추가할 수 있다. Python의 or는 왼쪽이 참이면 오른쪽을 평가하지 않아서, 빈 리스트에서 answer[-1]에 접근하지 않는다. 조건의 순서를 뒤집으면 빈 리스트 인덱스 오류가 날 수 있다.

추천 코드도 시간 O(n), 결과 공간 O(n)이다. 반복 상태와 분기 수를 줄인 표현이며 복잡도가 더 낮아진 것은 아니다. 로컬 5개 사례를 통과했지만 이 대체 코드는 프로그래머스에 별도 제출하지 않았다.
