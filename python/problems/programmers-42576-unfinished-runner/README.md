## 짧은 문제 요약

참가자 명단과 완주자 명단으로부터 완주하지 못한 한 사람의 이름을 찾는다. 동명이인이 있고 참가자는 최대 100,000명이므로, 이름의 존재 여부뿐 아니라 인원수와 처리 비용도 고려해야 한다. 전체 조건과 공식 예시는 원문에서 확인한다.

## 풀이와 검증 상태

- 최초 시도: 완주자를 참가자 리스트에서 한 명씩 삭제. 정확성 7개 통과, 효율성 5개 시간 초과, 58.3점.
- 최종 제출: 이름별 인원수를 딕셔너리에 저장하고 완주자마다 1을 차감. 정확성 7개·효율성 5개 통과, 100점.
- 위 채점 결과와 작성 코드는 각각 브라우저에서 직접 확인했다. 효율성 통과 화면의 실행 시간은 14.06~41.25ms였다. 이 수치는 해당 제출 환경의 결과이며 다른 환경의 성능 보장은 아니다.
- `solution.py`는 사용자가 작성한 최종 통과 코드다. 미사용 변수 `answer`와 변수명 `i`도 그대로 보존했다.
- 최초 리스트 삭제 풀이는 아래에 별도로 보존했다. 추천 코드는 제출 코드와 구분한다.
- 딕셔너리 접근, 문법, 마지막 반환 조건은 설명과 힌트를 받은 뒤 적용했다. 독립적으로 처음부터 완성한 풀이 또는 시간 제한 연습으로 기록하지 않는다. 소요 시간은 측정하지 않았다.

## 1. 처음 생각한 방법: 완주한 사람을 한 명씩 지우기

당시 화면에서 확인한 최초 리스트 삭제 풀이:

```python
def solution(participant, completion):
    answer = ''
    while completion:
        if completion[0] in participant:
            participant.remove(completion[0])
            completion.remove(completion[0])

    answer = participant[0]
    return answer
```

`remove`는 같은 값이 여러 개 있어도 첫 번째 하나만 지운다. 따라서 동명이인을 한 명씩 제외한다는 논리는 맞았다. 다만 다음 비용이 반복된다.

| 연산 | 의미와 비용 |
|---|---|
| `completion[0]` | 첫 원소 접근: O(1) |
| `name in participant` | 리스트를 순서대로 검색: 최악 O(n) |
| `participant.remove(name)` | 값을 검색한 뒤 뒤쪽 원소를 앞으로 이동: 최악 O(n) |
| `completion.remove(completion[0])` | 첫 원소는 바로 찾지만, 삭제 후 나머지 원소를 앞으로 이동: O(n) |

리스트가 줄어들어도 `n + (n-1) + ... + 1`만큼의 이동이 누적되어 전체 시간복잡도는 O(n²)이다. **반복문이 한 개라고 O(n)은 아니다. 반복문 안에서 호출한 연산의 비용도 포함한다.**

`in` 조건을 없애도 반복적인 `remove` 비용은 남는다. `completion.pop(0)`으로 바꿔도 첫 원소 삭제 뒤 이동이 필요하다. 반복문 문법만 바꾸는 것으로는 해결되지 않는다. 이 풀이는 입력 리스트 자체도 변경한다.

## 2. 바꾼 관점: 이름을 지우는 대신 인원수를 줄이기

이름마다 `참가한 인원수 - 완주한 인원수`를 기록한다.

```text
참가자: ["ana", "bob", "ana"]
완주자: ["ana", "bob"]

참가자 세기   → {"ana": 2, "bob": 1}
"ana" 차감   → {"ana": 1, "bob": 1}
"bob" 차감   → {"ana": 1, "bob": 0}
결과         → "ana"
```

동명이인이 있으므로 `set`으로 이름만 모으면 필요한 중복 정보가 사라진다. 참가자와 완주자 양쪽에 `"ana"`가 있다는 사실만으로는 한 명이 남았다는 것을 알 수 없다.

## 3. 이번에 배운 딕셔너리 문법

딕셔너리(`dict`)는 **키 → 값**을 저장한다. 이 문제에서는 키가 이름, 값이 인원수다. 리스트는 위치로 접근하고, 딕셔너리는 키로 접근한다.

```python
names = ["ana", "bob"]
names[0]                 # "ana"

counts = {}              # 빈 딕셔너리
counts["ana"] = 1        # 키와 값 추가
counts["ana"] += 1       # 기존 값 증가 → 2
counts["ana"] -= 1       # 기존 값 감소 → 1

"ana" in counts          # True: 키가 있는지 확인
"bob" in counts          # False
```

없는 키에 바로 `counts["bob"] += 1`을 하면 기존 값을 읽을 수 없어 `KeyError`가 난다. 처음 나온 이름은 1로 초기화하고, 이미 있는 이름만 1씩 증가시킨다.

```python
counts = {}
for name in participant:
    if name in counts:
        counts[name] += 1
    else:
        counts[name] = 1
```

문제 조건상 완주자는 모두 참가자이므로, 참가자를 센 뒤에는 완주자 이름에 해당하는 키가 있다.

```python
for name in completion:
    counts[name] -= 1
```

딕셔너리를 그대로 순회하면 **키**가 나온다. 값은 해당 키로 다시 조회한다.

```python
for name in counts:
    if counts[name] == 1:
        return name
```

`return`은 값을 돌려주고 함수 전체를 즉시 끝낸다. 따라서 정답을 찾은 뒤 `break`를 추가할 필요가 없다.

## 4. 막혔던 부분과 수정 이유

### 변수명 오타

초기 시도에서 매개변수 `participant` 대신 `participation`을 사용해 `NameError`가 났다. Python은 비슷한 철자를 같은 변수로 처리하지 않는다.

### 남은 인원수 0과 1을 반대로 해석

딕셔너리로 바꾼 뒤 마지막 조건을 `counts[i] == 0`으로 작성해 예제 3개가 모두 실패했다.

- `0`: 그 이름의 참가자가 모두 완주했다.
- `1`: 그 이름의 참가자 중 한 명이 아직 남아 있다.

따라서 `== 1`로 고쳤다. 완주하지 못한 사람이 정확히 한 명이라는 조건 때문에, 최종적으로 한 키의 값만 1이고 나머지는 모두 0이다. 값의 의미를 먼저 말로 설명하면 조건을 반대로 쓰는 실수를 줄일 수 있다.

## 5. 최종 코드의 시간·공간복잡도

참가자 수를 n, 서로 다른 이름 수를 u라고 하면:

| 단계 | 반복 횟수 | 평균 시간 |
|---|---|---|
| 참가자 인원수 세기 | n | O(n) |
| 완주자 인원수 차감 | n-1 | O(n) |
| 남은 이름 찾기 | 최대 u | O(u) |

반복문 세 개는 **중첩이 아니라 순서대로** 실행된다. 비용은 곱하지 않고 더하므로 전체 평균 시간복잡도는 O(n), 추가 공간은 O(u), 최악 O(n)이다. 해시 기반 딕셔너리의 조회·갱신은 평균 O(1)이고, 이름 길이가 최대 20자로 제한된 점을 전제로 한다. 모든 상황에서 최악 O(1)이라고 단정하지 않는다.

## 6. 추천 코드: 의미가 보이는 이름 사용

제출 코드의 `i`는 인덱스가 아니라 이름 문자열이다. `name`으로 쓰면 읽기 쉽다. 사용하지 않는 `answer`도 생략할 수 있다. 알고리즘과 복잡도는 동일하며, 이 수정이 큰 속도 개선을 만드는 것은 아니다. 지금은 새로운 축약 문법보다 직접 작성한 조건문을 유지한다.

<!-- recommended-solution -->
```python
def solution(participant, completion):
    counts = {}
    for name in participant:
        if name in counts:
            counts[name] += 1
        else:
            counts[name] = 1

    for name in completion:
        counts[name] -= 1

    for name in counts:
        if counts[name] == 1:
            return name
```

이 코드는 복습용 제안이며 `solution.py`를 덮어쓰지 않았다. 추천 코드의 플랫폼 제출은 하지 않았다.
